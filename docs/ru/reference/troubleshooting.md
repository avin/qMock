# Решение проблем

## Дашборд пуст

Каталог показывает файлы из `src/mocks/overrides` (или из вашего пути
`overrides`). Проверьте, что:

- Файлы — модули `.ts`.
- Имена файлов и папок не начинаются с `_`, а файлы не являются `.d.ts` или
  `.test.ts`.
- У модуля есть **экспорт по умолчанию** из `defineMockOverride` (или ровно один
  именованный экспорт оверрайда).

## Мой запрос не мокается

- **Формат ключа маршрута.** Он должен быть `METHOD /pathname` с методом в верхнем
  регистре и одним пробелом. Строку запроса не включайте.
- **Origin.** Моки отвечают на запросы, дошедшие до Vite. Если приложение
  обращается по абсолютному URL бэкенда, направьте его URL API для разработки на
  origin Vite.
- **Продакшн.** Моков нет в продакшн-сборках и под `vite preview`.
- **Wildcard-ы.** Точные обработчики побеждают. Среди wildcard-ов выигрывает
  первый объявленный, поэтому широкий `/*`, поставленный первым, может перекрыть
  более узкий.

## Мой оверрайд ничего не делает

- Он в списке **Active** и **включён** (чекбокс)?
- Ключ маршрута в точности совпадает с ключом обработчика? Для
  wildcard-обработчика оверрайд должен использовать **тот же wildcard-ключ**.
- Порядок: более поздний оверрайд мог заменить то, что произвёл ваш.
- Модификатор, вернувший `undefined`, оставляет текущий ответ.

## В модификаторе приходит `undefined`

Для новых маршрутов или маршрутов, отключённых через `null`, предыдущего тела нет.
Защититесь: `body => ({ ...(body ?? {}), extra: true })`.

## Тело JSON `null` превращается в пропуск запроса

Голый патч `null` отключает мок. Для настоящего JSON null используйте
`json(null)`.

## Тело запроса пустое при втором чтении

Тело можно прочитать один раз. Прочитайте его один раз через `readRequestBody`
или `readFormData` и переиспользуйте значение.

## Тесты

### Vitest: запросы не мокаются

Scope используют только вызовы, сделанные **внутри** `scope.run(...)` и
дождавшиеся завершения до его возврата. Перенесите рендеринг и проверки внутрь
колбэка.

### Playwright: запросы обходят моки

- Установите `use: { serviceWorkers: 'block' }`.
- Вызывайте `applyMocks` **до** `page.goto`.
- `context.request` и другие вызовы `APIRequestContext` не мокаются.

### Cypress: `cy.request()` не мокается

`cy.request()` использует отдельную сетевую подсистему. Пользуйтесь собственным
`fetch` или XMLHttpRequest приложения либо открывайте страницу через `cy.visit` и
работайте через интерфейс.

### Обработчик не загружается в Cypress

Здесь обработчики выполняются в браузере. Избегайте зависимостей, работающих
только в Node, и читайте тела через `readRequestBody` или `readFormData`, а не
через внутренности `request.raw`.

### Алиасы не разрешаются в тестах

Пути из `tsconfig.json` работают по умолчанию. Для алиасов, определённых только
в Vite, передайте `alias: { '@': './src' }` или импортируйте конфигурацию через
ваш тест-раннер.

## Всё ещё не получается?

Создайте issue на [github.com/avin/qMock/issues](https://github.com/avin/qMock/issues),
приложив конфиг Vite, нужный обработчик или оверрайд и запрос, который, по вашему
мнению, должен был замокаться.
