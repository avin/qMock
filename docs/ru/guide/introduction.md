# Введение

QMock — это плагин для Vite, который во время разработки отдаёт моковые ответы
API, и дашборд, позволяющий менять эти ответы без правки кода и перезапусков.
Те же определения моков можно использовать в автоматических тестах.

## Проблема

Фронтенд-разработка постоянно упирается в одни и те же ситуации:

- Бэкенд ещё не готов или недоступен с вашей машины.
- Нужно увидеть состояние ошибки, пустое состояние или вариант экрана для
  «администратора», а настоящий бэкенд не воспроизведёт их по запросу.
- Тесты ходят в реальный или общий мок-сервер, и подготовка одного теста влияет
  на другой.

Зашивать фейковые данные прямо в компоненты — плохое решение. QMock даёт для
этого структурированное место.

## Модель

В QMock три идеи. Всё остальное в документации — детали поверх них.

### 1. Handlers (обработчики): базовое API

**Обработчик** сопоставляет маршрут, например `GET /api/user`, с ответом.
Вместе ваши обработчики описывают, как API ведёт себя, когда всё в порядке.

```ts
'GET /api/user': { id: 'demo', name: 'Demo User' }
```

### 2. Overrides (оверрайды): сценарии поверх

**Оверрайд** — небольшой модуль, который меняет часть этих ответов: возвращает
ошибку, меняет поле или добавляет маршрут. У оверрайдов могут быть
**параметры** (чекбокс, текстовое поле, выпадающий список), так что один файл
покрывает много вариаций.

### 3. Список активных: композиция сценариев

В дашборде вы перетаскиваете оверрайды в список **Active**. Они выполняются
**сверху вниз**, и каждый получает ответ, который произвёл предыдущий. Порядок —
это и есть механизм композиции: «медленный пользователь», а затем «пользователь
с ошибкой» ведёт себя иначе, чем наоборот.

```text
Базовый обработчик →  { id: 'demo', name: 'Demo User' }
  + User profile   →  { id: 'demo', name: 'Taylor', role: 'admin' }
  + Force error    →  503 { error: 'Service unavailable' }
```

## Два места применения

| Где                                      | Как выбираются сценарии                              | Сохраняется ли?                              |
| ---------------------------------------- | ---------------------------------------------------- | -------------------------------------------- |
| **Разработка** (Vite)                    | Вы выбираете их в дашборде на `/__apiMocks`           | Сохраняется в `.mock-overrides.json`         |
| **Тесты** (Vitest, Playwright, Cypress)  | Каждый тест перечисляет нужные ему оверрайды         | Нет. Каждый тест стартует с чистого листа    |

Настройки дашборда никогда не попадают в тесты, а тестовые сценарии никогда не
трогают сохранённое состояние дашборда.

## Чем QMock не является

- Он **только для разработки**. Моки и дашборд не попадают в продакшн-сборку и не
  отдаются командой `vite preview`.
- Это **не отдельный мок-сервер**. Он работает внутри dev-сервера Vite либо
  внутри процесса или браузерного контекста вашего тест-раннера.
- Нужны **Vite** и **Node.js 22.12 или новее**. QMock — это ESM.
